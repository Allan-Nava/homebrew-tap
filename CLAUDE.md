# CLAUDE.md — homebrew-tap

**homebrew-tap** (`github.com/Allan-Nava/homebrew-tap`): il tap Homebrew dei progetti Allan-Nava, usato come `brew tap Allan-Nava/tap` (Homebrew taglia il prefisso `homebrew-`). È un repo di **distribuzione**, non di sviluppo: cask generati + gli script e i workflow che li generano e li validano. Zero codice applicativo, zero build. Oggi cinque cask di quattro progetti: `Casks/checkfleet.rb` (CLI [checkfleet](https://github.com/Allan-Nava/checkfleet)), `Casks/checkfleet-desktop.rb` (app Wails della stessa release), `Casks/segcheck.rb` (CLI [segcheck](https://github.com/Allan-Nava/segcheck)), `Casks/ladder-bench.rb` (CLI [ladder-bench](https://github.com/Allan-Nava/ladder-bench), unico cask con una dipendenza: `ffmpeg`) e `Casks/abrsim.rb` (CLI [abrsim](https://github.com/Allan-Nava/abrsim)).

## Regole di lavoro (SEMPRE)

- **I file in `Casks/` sono generati e NON si editano a mano.** Due sorgenti distinte, non confonderle:
  - `checkfleet.rb`, `segcheck.rb`, `ladder-bench.rb`, `abrsim.rb` → **GoReleaser**, dal repo del progetto, a ogni tag `v*` (`# This file was generated by GoReleaser. DO NOT EDIT.`, commit `Brew cask update for <progetto> version vX.Y.Z`). Un fix si fa nel `.goreleaser.yaml` **di quel progetto** → `homebrew_casks` e si rilascia; il marker in testa al file è anche ciò che divide i due bucket di `brew style` (vedi sotto).
  - `checkfleet-desktop.rb` → **`scripts/render-desktop-cask.sh`** di questo repo, perché GoReleaser non builda l'app desktop (lo fa `desktop.yml` upstream, che allega lo zip alla release *dopo*). Un fix si fa nel template dentro lo script, poi si rigenera.
- **Nessun bump manuale di `version`/`sha256`**: i checksum si calcolano sugli asset reali della release. A mano = install rotta con `SHA256 mismatch`.
- **MAI `git push`** — lo fa sempre l'utente. MAI `Co-Authored-By` nei commit.
- **Qui non si taggia e non c'è CHANGELOG**: versioning e release vivono nel repo del progetto. La history di questo repo è quasi interamente bot: non inquinarla con commit rumorosi.
- **Gate prima di chiudere** (cask, script o workflow toccati): `scripts/ci-place-tap.sh` + `brew style` + `brew info --cask` + `brew audit --cask --online` verdi. Se si cambia il cask desktop, rigenerarlo davvero con lo script e verificare il diff.
- **Todo → `BACKLOG.md`** (sorgente unica, id stabili `HT-n`). Gli item che vanno chiusi upstream lo dichiarano; non si "aggirano" toccando `Casks/`.
- **Le issue si generano dal backlog, non a mano**: `scripts/backlog-sync.sh` (workflow `backlog-sync.yml`) tiene una issue per ogni `HT-n` — spuntare l'item la chiude, togliere la spunta la riapre. Aprire o chiudere issue a mano crea divergenza col file. Le due issue di stato (`Fix upstream arrivato: HT-n` dal watcher, `Tap rotto: la CI dei cask è rossa` dal report della CI) passano da `scripts/gh-issue.sh`, idempotente per titolo: apre se manca, riapre se chiusa, tace se già aperta.
- **Niente segreti**: `HOMEBREW_TAP_GITHUB_TOKEN` (il token con cui GoReleaser pusha qui) è un secret della CI di checkfleet e non deve mai comparire in questo repo.
- Il README è l'unica doc user-facing: se cambiano i comandi d'installazione o si aggiunge un cask, aggiornarlo.

## Comandi

```bash
scripts/ci-place-tap.sh                          # il checkout diventa allan-nava/tap in Library/Taps
# style: due bucket (mai sul tap, mai --fix). Cask generati da GoReleaser:
brew style --except-cops Cask/Desc,Style/NumericPredicate,Layout/EmptyLinesAroundBlockBody,Cask/StanzaOrder,Cask/StanzaGrouping,Layout/FirstArrayElementIndentation \
  "$(brew --repository)"/Library/Taps/allan-nava/homebrew-tap/Casks/{checkfleet,segcheck,ladder-bench,abrsim}.rb
# Cask reso da noi: nessuna esclusione, deve essere pulito.
brew style "$(brew --repository)"/Library/Taps/allan-nava/homebrew-tap/Casks/checkfleet-desktop.rb
brew info --cask allan-nava/tap/checkfleet       # il cask si carica?
# audit: senza token sono 60 richieste/ora PER IP e l'audit muore a metà (HT-24)
HOMEBREW_GITHUB_API_TOKEN="$(gh auth token)" brew audit --cask --online allan-nava/tap/checkfleet
brew install --cask allan-nava/tap/checkfleet    # in headless: HOMEBREW_NO_REQUIRE_TAP_TRUST=1
brew reinstall --cask checkfleet                 # ri-esegue il postflight (quarantine)
brew uninstall --cask --zap checkfleet-desktop
scripts/render-desktop-cask.sh [vX.Y.Z]          # rigenera il cask desktop (default: ultima release)
scripts/render-readme-casks.sh                   # rigenera gli elenchi dei cask nel README
scripts/render-readme-casks.sh --check           # exit 1 se il README è stantio
scripts/backlog-sync.sh --dry-run                # anteprima del sync BACKLOG.md → issue
scripts/check-upstream-fixes.sh                  # TSV landed/pending/done dei fix attesi da upstream
scripts/sync-cask-versions.sh                    # drift cask ↔ release upstream (default --check)
scripts/sync-cask-versions.sh --apply abrsim     # risincronizza dagli asset reali della release
DRY_RUN=1 scripts/gh-issue.sh ensure-open "<titolo>" body.md <label>
```

## Struttura

- `Casks/checkfleet.rb` — generato da GoReleaser: `version`, `on_macos`/`on_linux` × `on_intel`/`on_arm` con url+sha256 dei tarball della release, `binary "checkfleet"`, `livecheck { skip }`, `postflight` anti-quarantine.
- `Casks/segcheck.rb` — generato da GoReleaser, stessa forma di `checkfleet.rb` (macOS+Linux × intel/arm, `binary "segcheck"`, `livecheck { skip }`, postflight anti-quarantine). Il suo postflight confronta `exit_status == 0`: è l'offense `Style/NumericPredicate` di HT-21, fix nel `.goreleaser.yaml` di segcheck.
- `Casks/ladder-bench.rb` — generato da GoReleaser; l'unico con `depends_on formula: ["ffmpeg"]` (serve libvmaf, che è un'opzione di build di ffmpeg). GoReleaser rende quell'array indentato male e senza riga vuota sopra: tre offense non correggibili né qui né nel repo upstream (HT-22).
- `Casks/abrsim.rb` — generato da GoReleaser, stessa forma degli altri CLI (macOS+Linux × intel/arm, `binary "abrsim"`, `livecheck { skip }`, postflight anti-quarantine con `.exit_status.zero?`).
- `Casks/checkfleet-desktop.rb` — generato dallo script: `app "checkfleet.app"`, `depends_on :macos`, postflight anti-quarantine sul bundle, `zap trash` sui path di `com.wails.checkfleet`.
- `scripts/render-desktop-cask.sh` — risolve l'asset `checkfleet-desktop_v*_darwin_universal.zip` della release, calcola lo sha256, verifica che il bundle sia alla radice dello zip e che il nome dell'asset combaci con l'url interpolato (`v#{version}`), poi rende il cask. Exit 2 = asset non ancora pubblicato → il workflow lo tratta come skip.
- `scripts/ci-place-tap.sh` — copia il checkout in `Library/Taps/allan-nava/homebrew-tap` (i cask fuori da un tap sono rifiutati da Homebrew).
- `scripts/check-workflows.rb` — coerenza dei workflow: ogni `needs` punta a un job esistente, ogni `needs.<job>.result` è dichiarato. Exit 1 con `::error::` per ogni problema.
- `.github/workflows/cask-ci.yml` — style + load, install su `macos-14`/`macos-13` (la versione del binario deve combaciare con quella del cask, quarantine rimossa, smoke `check tcp`), install del bundle desktop, `audit --online`. Su push/PR, lunedì, e a mano.
- `scripts/backlog-sync.sh` — parser awk di `BACKLOG.md` (item `HT-n`, milestone = sezione) + reconcile delle issue via `gh`, idempotente, `--dry-run`. Il ciclo legge gli item dal **fd 3** perché sullo stdin ci sono i comandi `gh`.
- `scripts/check-upstream-fixes.sh` — audit dei cask generati: dice quali fix attesi da upstream sono atterrati — HT-1/HT-2/HT-7 su `Casks/checkfleet.rb` (`CASK`), HT-21 su `Casks/segcheck.rb` (`SEGCHECK_CASK`). TSV `landed|pending`, exit 0 sempre.
- `scripts/render-readme-casks.sh` — rigenera tre regioni fra marker nel README (install, tabella, uninstall) leggendo solo `Casks/*.rb` (HT-27). La prosa resta a mano. `--check` esce 1 col diff; lo gira `cask-sync.yml` su ogni push a `Casks/**`, e `cask-ci.yml` solo come `::warning::`.
- `scripts/sync-cask-versions.sh` — confronta la `version` di ogni cask generato con `releases/latest` del progetto e, con `--apply`, la risincronizza ricalcolando i `sha256` dagli asset veri (HT-26). Tocca solo `version`/`sha256`, solo nei file col marker GoReleaser, e rifiuta se il template cambia forma. TSV `sync|drift|synced|skip|error`.
- `.github/workflows/cask-sync.yml` — sync + render del README: gira ogni 6h e **a ogni push su `Casks/**`** (cron sfasato da `desktop-cask.yml`, stesso gruppo `tap-write`) su ubuntu, committa e tiene la issue `Cask in drift: una release non è arrivata nel tap`. Il render del README gira **sempre**, anche senza drift: un cask nuovo arriva già allineato, è la doc che manca. Nessun loop: pusha col GITHUB_TOKEN, e quei push non innescano workflow. La validazione la fa Cask CI sul push che ne esce.
- `scripts/gh-issue.sh` — issue idempotente per titolo (`ensure-open` / `ensure-closed`), usata dal watcher dei fix e dal report della CI. `DRY_RUN=1` per provare.
- `.github/workflows/backlog-sync.yml` — sync backlog → issue su push che toccano `BACKLOG.md`/lo script/il workflow, e a mano.
- `.github/workflows/desktop-cask.yml` — rigenera e committa il cask desktop: `repository_dispatch` (`checkfleet-desktop-release`, da attivare upstream — HT-5), cron ogni 6h, manuale con tag. Valida prima di pushare, `concurrency: tap-write`, `pull --rebase` + retry.

## Trappole note / regole tecniche

- **I cask devono stare in un tap**: `brew info --cask ./Casks/x.rb` → "Homebrew requires casks to be in a tap". Perciò in locale e in CI si passa da `scripts/ci-place-tap.sh` e si usano i token (`allan-nava/tap/<cask>`), non i path.
- **`brew style` ignora un `.rubocop.yml` del tap** (HT-14): usa il suo, `$(brew --prefix)/Library/.rubocop.yml`. Non provare a forzarlo dalla CLI — `brew style --config ...` oggi esce con `Error: invalid option: --config` (Homebrew 6.0.18), quel flag non c'è. Le esclusioni vivono nei workflow come `--except-cops`.
- **Le esclusioni di `brew style` valgono SOLO per i cask generati da GoReleaser** (HT-22): il job `lint` divide i file in due bucket sul marker `DO NOT EDIT` in testa — GoReleaser con `--except-cops`, `render-desktop-cask.sh` **senza nessuna esclusione** (è nostro: lì un'offense si corregge). Non allargare la lista al bucket nostro, e non aggiungere un cop nuovo senza un item che dica come si torna a zero: `Cask/Desc` → HT-2 e `Style/NumericPredicate` → HT-21 sono fix upstream (sorvegliati da `check-upstream-fixes.sh`); `Cask/StanzaOrder`, `Cask/StanzaGrouping`, `Layout/FirstArrayElementIndentation`, `Layout/EmptyLinesAroundBlockBody` sono il template di GoReleaser e non sono correggibili in nessuno dei nostri repo. Attenzione: la lista dipende dalla versione di Homebrew del runner — in locale con 6.0.18 le offense sono 19, su `macos-latest` erano 4.
- **Non reintrodurre il workflow template `brew test-bot --only-tap-syntax`** (era `.github/workflows/ci.yml`, rimosso con HT-19): stila l'intero tap e in questo repo è rosso per costruzione — 8 offense, fra cui le due del cask generato da GoReleaser, che test-bot non permette di escludere (il `.rubocop.yml` del tap viene ignorato) e che tornano a ogni release, più shfmt su tutti gli script. `cask-ci.yml` copre già lo stesso terreno con lo scoping giusto.
- **MAI `brew style --fix`, e `brew style` sempre sui file `Casks/*.rb`, mai sul tap**: passato un tap, Homebrew stila anche gli script con shellcheck+shfmt, e quel formatter **tronca l'heredoc** di `render-desktop-cask.sh` — il cask reso perde tutto ciò che sta dopo `postflight do` (verificato). Gli script si controllano con shellcheck normale (job dedicato in `cask-ci.yml`, che con le impostazioni di default è verde: SC2250/SC2292 sono cop opzionali che solo Homebrew abilita).
- **Togliere un job da un workflow senza togliere i suoi riferimenti rende l'intero workflow invalido**: GitHub non segnala "job mancante", registra un run `failure` **senza nessun job e senza log** (successo: rimosso `shellcheck`, il job `report` lo aveva in `needs` → run 30241681227 morto). Prima di committare: `scripts/check-workflows.rb` (gira anche in CI dentro il job `shellcheck`).
- **Un commento che inizia con `# shellcheck` viene letto come direttiva** (SC1073 "Couldn't parse this shellcheck directive"): se si vuole *nominare* shellcheck in un commento, non metterlo come prima parola. Le SC2016 in `backlog-sync.sh` sono disattivate apposta — i backtick lì sono markdown per il corpo della issue, non command substitution.
- **`brew audit --online` senza token esaurisce l'API di GitHub** (HT-24): l'audit chiama l'API (`audit_github_prerelease_version` e simili) e senza token il limite è **60 richieste/ora per IP** — sui runner hosted l'IP è condiviso, quindi il budget non è nostro. Con quattro cask ci siamo finiti dentro: `API rate limit exceeded ... (60 limit)` → `exception while auditing <cask>`, che Homebrew conta come errore (`add_error` poi `ofail`), quindi **job rosso** e issue "Tap rotto" per un motivo che col tap non c'entra niente. In CI c'è `HOMEBREW_GITHUB_API_TOKEN: ${{ github.token }}` nell'`env` di `cask-ci.yml` e `desktop-cask.yml` (1000/ora, read-only, nessun secret da creare). In locale: `HOMEBREW_GITHUB_API_TOKEN="$(gh auth token)"`. Verificato che sia davvero quella la variabile usata da questo code path: con un token finto lo stesso audit fallisce con `GitHub API Error: Bad credentials`.
- **Il `postflight` con `xattr -dr com.apple.quarantine` è VOLUTO** in entrambi i cask: niente firma né notarizzazione, senza quello Gatekeeper blocca binario e bundle. Non "sistemarlo". Per il CLI si cambia in `hooks.post.install` upstream.
- **`livecheck { skip "Auto-generated on release." }` è voluto**: la versione la spinge la release (GoReleaser per il CLI, `desktop-cask.yml` per l'app). Un livecheck sarebbe una seconda fonte di verità.
- **`depends_on macos: ">= :high_sierra"` non si può usare**: quella forma è deprecata e la versione è sotto il minimo supportato → il cask non si carica più. Nel cask desktop serve il `depends_on :macos` nudo, che è anche quello che pretende il cop `Homebrew/OSDependsOn` per i cask con artifact `app`.
- **Un cask con solo `binary` NON è macOS-only**: `Cask::Artifact::Binary` non è in `MACOS_ONLY_ARTIFACTS`, quindi `checkfleet` si installa anche su Linuxbrew 6+ e il ramo `on_linux` del cask generato è reale (il postflight `xattr` si auto-salta lì). L'app desktop invece è macOS-only per via dell'artifact `app`.
- **Gli elenchi dei cask nel README sono generati** (HT-27): stanno fra marker `<!-- BEGIN generated: … -->` e li riscrive `scripts/render-readme-casks.sh` da `Casks/*.rb`. Non editarli a mano — al prossimo push su `Casks/**` il workflow li rigenera e il tuo testo sparisce. La prosa fuori dai marker invece è a mano ed è quella che vale la pena curare.
- **Il tap può restare indietro senza che niente diventi rosso** (HT-26): se il PAT del tap scade (`HOMEBREW_TAP_TOKEN` per segcheck/abrsim, `HOMEBREW_TAP_GITHUB_TOKEN` per checkfleet/ladder-bench), la release upstream pubblica tutto e poi fallisce **solo** sul push qui. Il cask resta alla versione vecchia e ogni gate resta verde, perché `livecheck { skip }` non guarda upstream. Il detector è `scripts/sync-cask-versions.sh` (workflow `cask-sync.yml`, ogni 6h) che in `--apply` risincronizza anche; ma la causa si sistema **rinnovando il token nel repo del progetto**, altrimenti il prossimo tag si ferma di nuovo.
- **Un commit locale divergente rompe la release upstream**: GoReleaser pusha qui durante la release; se `main` ha commit che conflittano, quella release fallisce a metà. Tenere il repo allineato a `origin/main`.
- Aggiungere un nuovo progetto al tap si fa **dal progetto**: `homebrew_casks` nel suo `.goreleaser.yaml` con `repository: {owner: Allan-Nava, name: homebrew-tap}` + secret `HOMEBREW_TAP_GITHUB_TOKEN`. Non creando il file a mano qui.
